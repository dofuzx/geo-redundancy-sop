# SOP Step-4 语义复核报告：区分「合法队列拆分」与「变脸重投」

> 语料：Tier1+2+3 严格同口径合并（**61 系列 / 5999 样本 / 7837 对 r≥0.97**）
> 复核依据：系列级投稿者/机构/邮箱、PMID、SuperSeries 关系、共享 GSM、以及 **r=1.0000 精确重复计数**
> 前置修正：本次复核前已修复检测器样本归因缺陷（详见第五节），否则判定会被系统性误导

## 一、核心判据（本次确立的分层标准）

| 层 | 判据 | 结论倾向 |
|---|---|---|
| **L1 精确复制** | 存在成批 **r=1.0000** 的配对 | 同一批物理阵列被重复投递 → **去重** |
| **L2 身份掩盖** | L1 成立，但两系列**不共享任何 GSM**（换了新编号） | **变脸（face-swap）**，最严重，Layer A 无法发现 |
| **L3 同组复用** | 同一投稿人/机构/邮箱，高 r 但未达 1.0 | 同一队列跨文章再利用 → 视用途**部分去重** |
| **L4 异源相似** | 不同投稿人+机构，r 在 0.97–0.99 且无精确重复 | 独立队列的生物学相似 → **KEEP** |
| **L5 伪相关** | 高 r 但伴随数据集自身内部基线异常抬高 | **KEEP**，属方法学假阳性，需改判据而非删数据 |

### ④ GSE17536 ↔ GSE29621（2851 对，本次最大）—— 判定为 **伪相关，KEEP**

这是你特别关注的一对，结论明确：**它不是样本重复**。

| 证据 | 数值 |
|---|---|
| 对数 / 峰值 r | 2851 / 0.9991 |
| **r=1.0000 的配对数** | **0** |
| GSE29621 自身内部 ≥0.97 的比例 | **32.0%**（中位数 r=0.966） |
| 对照：GSE29621 × GSE17536（无人怀疑的一对）≥0.97 | 24.8% |
| 投稿者 | Vanderbilt 的 Pengcheng Lu **vs** Moffitt 的 Dung-Tsa Chen（不同人、不同机构、不同国） |

**判定理由**：真实重复会产生批量的 r=1.0000（见 ①②③ 均为 30–104 对精确 1.0），而这一对**零个 1.0**；且 GSE29621 与任何系列交叉都稳定落到 25% 左右的 ≥0.97，属**数据集自身的基线偏高**所致。

**GSE29621 应被标记为「高基线数据集」**，处理方法应是**加入基线感知判据**（如要求交叉 r 显著高于双方自身内部分布的 p99，或统一提高至 0.99），而不是删除样本。这是本次复核发现的最重要的**方法学局限**，建议写成论文的 Limitation + Method 改进点。

## 五、⚠️ 修复的检测器缺陷（本次复核的直接产物）

**问题**：`analyze_tier.py` 用 `{样本名: 系列}` 字典归属系列。当同一 GSM 同时属于多个系列时（SuperSeries/样本复用），**后加载的系列会覆盖先加载的**，造成：
1. 共享 GSM 的重复对被判为「同系列」而**静默丢失**；
2. 相关对被**错误归属**给后加载的系列（例：GSE17536 与 GSE29621 的 2851 对，原先被算到 GSE17538 名下）。

**修复**：改为按下标维护 `series_at` / `root_at`，与列位置一一对应，不再依赖样本名唯一性；顺带把交叉判定向量化。

**修复前后对比**：

| | 对数 | 可见的关键发现 |
|---|---|---|
| 修复前 | 10244 | GSE17538×GSE29621 的 5702 对（归属错误） |
| 修复后 | 7837 | GSE17536×GSE29621 的 2851 对（正确）；**新发现 GSE14580↔GSE16879 的 30 个精确重复** |
